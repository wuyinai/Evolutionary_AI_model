  - author: 作者

  - metadata: 元数据（JSON）
- 索引: uk_user_name（用户ID+技能名唯一索引）
- ID生成策略: 雪花算法（避免skill_name中的特殊字符导致MinIO路径问题）

## 文件存储结构

### 技能包存储路径（MinIO）
- 存储位置: MinIO对象存储
- 存储路径: `skills/{user_id}/{skill_id}/`
- 示例: `skills/123/1847293847562/SKILL.md`
- 配置位置: [application.yml](file:///d:/Project/MyProject/Evolutionary_AI_model/Evolutionary_AI_model/src/main/resources/application.yml) (MinIO配置)
- **重要**: 使用skill_id而不是skill_name作为路径，避免skill_name中的特殊字符导致MinIO路径问题

### MinIO对象结构
- 基础路径: `skills/{user_id}/{skill_id}/`
- 包含所有解压后的文件（SKILL.md、模板文件、脚本文件等）
- 文件路径示例:
  - `skills/123/1847293847562/SKILL.md`
  - `skills/123/1847293847562/templates/viewer.html`
  - `skills/123/1847293847562/templates/generator_template.js`

### SKILL.md文件格式
- 必须存在于ZIP包根目录
- YAML头信息格式:
```yaml
---
name: skill-name
displayName: Skill Display Name
description: Skill description
version: 1.0.0
author: Author Name
---
```

## 技术要点

### 1. 安全性
- ZIP slip攻击防护（路径校验）
- 文件类型校验（仅接受.zip）
- 用户权限校验（JWT token）
- 技能名称唯一性校验
- **文件名特殊字符处理**：
  - 前端校验：只允许字母、数字、下划线、连字符
  - 后端兜底：将特殊字符替换为下划线（MinIO不支持特殊字符）

### 2. 异常处理
- 全局异常处理: [GlobalExceptionHandler.java](file:///d:/Project/MyProject/Evolutionary_AI_model/Evolutionary_AI_model/src/main/java/com/example/evolutionary_ai_model/handler/GlobalExceptionHandler.java)
- 业务异常: BusinessException
- 日志记录: 所有异常均记录日志

### 3. 文件处理
- 使用Hutool工具类简化文件操作
- 临时目录自动清理
- 支持ZIP文件解压（UTF-8编码）
- 文件存储到MinIO对象存储
- 支持文件批量上传和删除

### 4. 前端交互
- 拖拽上传支持
- 实时状态更新
- 启用/禁用开关动画
- 响应式布局
- **文件名校验**：前端校验文件名，不允许MinIO不支持的特殊字符（空格、连字符、中文等）

## API接口列表

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 上传技能包 | POST | `/skills/upload` | 上传ZIP文件 |

| 删除技能 | DELETE | `/skills/{skillId}` | 删除技能及文件 |

## 开发规范遵循

### 1. 三层架构
- Controller: 仅负责接收请求、参数校验、调用Service
- Service: 负责核心业务逻辑、事务管理
- Mapper: 仅负责数据持久化

### 2. 注释规范
- 所有类添加用法注释
- 关键方法添加注释说明

### 3. 日志规范
- 所有异常捕获处记录日志
- 关键业务操作记录日志
- 不打印敏感信息

### 4. 设计模式
- Service层使用策略模式处理不同业务场景
- 文件处理使用模板方法模式
- 异常处理使用全局异常处理器
