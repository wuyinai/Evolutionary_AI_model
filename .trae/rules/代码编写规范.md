一、三层架构强制要求
所有后端业务功能代码必须严格遵循三层架构（表现层、业务逻辑层、数据访问层），层级职责分明，禁止跨层调用。

表现层（Controller）：只负责接收请求、参数校验、调用业务层、返回响应。严禁包含任何业务逻辑或直接操作数据库。

业务逻辑层（Service）：负责核心业务处理、事务管理。严禁直接处理HTTP请求或直接编写SQL。

数据访问层（Repository/DAO）：只负责数据持久化操作。严禁包含业务逻辑。

代码包结构需清晰体现分层，如 controller、service、repository（或 dao）。

每一天新增加接口时将请求地址和测试数据标识出来。
二、日志规范
2.1 必须记录日志的场景
以下情况必须使用日志记录，不得遗漏：

所有异常捕获处（try-catch、全局异常处理）

关键业务操作（创建、更新、删除等）

外部接口调用（请求参数和响应结果）

数据库操作失败时

参数校验失败时

系统启动或关键配置加载时

2.2 禁止打印明文密码
严禁在日志中输出任何形式的明文密码，包括但不限于：

用户登录密码

数据库连接密码

第三方服务的密钥、Token

请求参数中包含的 password、passwd、secret、token 等敏感字段

处理方式：打印前对敏感字段进行脱敏处理，如替换为 ******，或直接移除该字段。

2.3 日志级别使用
ERROR：系统错误、需要人工介入的问题

WARN：潜在风险、降级处理、可恢复的异常

INFO：关键业务流程节点、外部调用

DEBUG：调试信息，生产环境不输出

三、注释规范
3.1 类注释（强制）
每个类在定义之前、类注解之上，必须添加以下格式的注释：

text
/**
 * 用法：简洁说明该类的职责与使用场景，通常包含以下要素：
 * 1. 该类所归属的层级（Controller/Service/Repository）
 * 2. 该类处理的核心业务实体或功能
 * 3. 调用链路中该类所处的位置与上下游依赖
 * 4. 若涉及工厂模式、策略模式等设计思路，需说明扩展方式
 */
示例：

java
/**
 * 用法：用户管理Controller，负责接收前端用户相关请求。
 * 调用 UserService 处理业务逻辑，返回统一响应格式。
 */
@RestController
@RequestMapping("/api/users")
public class UserController {
    // ...
}
java
/**
 * 用法：订单服务实现类，负责订单创建、状态流转等核心业务逻辑。
 * 依赖 OrderRepository 进行数据持久化，依赖 PaymentService 处理支付。
 */
@Service
public class OrderServiceImpl implements OrderService {
    // ...
}
3.2 代码行注释
需要在代码行上方或右侧添加注释时，使用 # 注解内容 格式（适用于 Python），Java / Go / TypeScript 等语言使用对应的行注释符号（即语言原生单行注释），保持团队成员可快速理解代码逻辑。

示例：

java
// 校验用户是否存在，若不存在则抛出业务异常
User user = userRepository.findById(userId)
        .orElseThrow(() -> new BusinessException("用户不存在"));
四、日志脱敏代码示例
以下示例展示了如何在捕获异常和记录日志时，对密码等敏感信息进行脱敏处理：
java
/**
 * 用法：用户服务实现类，负责用户注册、登录等业务逻辑。
 * 依赖 UserRepository 进行数据持久化，密码使用 BCrypt 加密存储。
 */
@Service
public class UserServiceImpl implements UserService {

    private static final Logger logger = LoggerFactory.getLogger(UserServiceImpl.class);

    public User login(String username, String password) {
        try {
            // 打印日志前脱敏，记录查询的用户名但不记录密码
            logger.info("用户登录请求，用户名: {}", username);
            User user = userRepository.findByUsername(username);
            if (user == null || !passwordEncoder.matches(password, user.getPassword())) {
                logger.warn("用户登录失败，用户名: {}", username); // 失败日志同样不记录密码
                throw new BusinessException("用户名或密码错误");
            }
            logger.info("用户登录成功，用户名: {}", username);
            return user;
        } catch (BusinessException e) {
            throw e;
        } catch (Exception e) {
            // 异常日志中不打印密码参数，只记录用户名用于排查
            logger.error("用户登录异常，用户名: {}", username, e);
            throw new SystemException("系统异常，请稍后重试");
        }
    }
}
