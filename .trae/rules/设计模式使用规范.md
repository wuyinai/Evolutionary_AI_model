后端设计模式规范（Java 版）

## 一、核心原则

在编写后端代码时，Agent **必须主动识别并应用合适的设计模式**，以达成：

- **解耦模块**：减少模块间直接依赖
- **封装变化**：将容易变化的行为与稳定结构分离
- **职责单一**：每个类仅承担一类职责

## 三、按目录应用设计模式的强制规则

### 1. `service/` 层

- **必须**将核心业务逻辑与可变策略分离 → 应用 **策略模式**
- **必须**将对象创建逻辑与使用逻辑分离 → 应用 **工厂模式**（简单工厂 / 工厂方法）
- **禁止**在 `service/impl/` 中出现复杂条件分支（if-else / switch）用于选择不同算法

### 2. `controller/` 层

- **仅**负责请求接收、参数校验、响应封装
- **必须**将请求处理流程中可变的步骤（如不同渠道的订单处理）抽取到 `handler/`
  → 应用 **模板方法模式**

### 3. `handler/` 层

- 用于处理 **可插拔的业务步骤** 或 **责任链式处理**
  → 应用 **责任链模式** 或 **策略模式 + 链式调用**
- 每个 Handler 必须实现统一接口，且不依赖具体调用方

### 4. `service/factory/`

- **必须**集中管理复杂对象的创建过程
- **禁止**在业务代码中直接 `new` 策略类或算法类

### 5. `service/strategy/`

- **必须**定义策略接口
- 每个策略类封装 **一类独立变化的业务规则**（如折扣计算、模型选择、评分算法）

### 6. `entity/`、`dto/`、`vo/`

- **禁止**包含任何业务逻辑或处理逻辑
- **仅**作为数据载体

### 7. `mapper/` 层

- **仅**负责数据库访问
- **禁止**在 Mapper 中编写业务判断逻辑

### 8. `config/` 层

- 用于 **依赖注入配置**、**策略注册**、**工厂 Bean 注册**
  → 应用 **注册表模式** 或 **依赖注入模式**

### 9. `util/` 层

- **只允许**无状态的纯函数工具类
- **禁止**持有业务依赖或可配置状态

## 四、模式选择指引（Agent 决策表）

| 场景 | 推荐模式 | 目录位置 |
|------|----------|----------|
| 多种算法/计价/推荐方式 | 策略模式 | `service/strategy/` |
| 复杂对象创建过程 | 工厂模式 | `service/factory/` |
| 请求处理流程有固定步骤但部分可变 | 模板方法模式 | `handler/` |
| 多个处理器依次处理同一请求 | 责任链模式 | `handler/` |
| 通知、事件、触发类操作 | 观察者模式（或 Spring Event） | `handler/` 或单独 `event/` |
| 状态机类业务（如任务状态流转） | 状态模式 | `handler/` 或 `service/state/` |
| 对外部系统调用需要统一入口 | 外观模式 | `service/facade/`（如有需要可新增） |
| 缓存访问或代理控制 | 代理模式 | 通过 Spring AOP 或 `handler/` |

## 五、强制禁止的“坏味道”

- ❌ 一个方法超过 40 行
- ❌ 同一类中存在两个及以上不同的变更原因
- ❌ 使用 `instanceof` 或类型判断来选择行为 → **必须改为策略模式**
- ❌ 在 Service 中直接 `new` 另一个 Service 的具体实现 → **必须通过工厂或 DI**
- ❌ 在 Controller 中编写业务规则
- ❌ 将策略逻辑写在 `impl/` 类中而不提取到 `strategy/`

## 六、团队协作收益

- 新人看到 `strategy/` → 立即知道“这里是可替换的算法”
- 看到 `factory/` → 立即知道“这里是对象创建逻辑”
- 看到 `handler/` → 立即知道“这里是责任链或模板步骤”

**无需额外注释，包结构即设计文档。**

## 七、Vibe Coding 执行指令（给 Agent）

> 在生成任何后端 Java 代码前：
>
> 1. 识别当前操作属于哪个目录
> 2. 判断是否存在可变行为、复杂创建逻辑、多步骤流程
> 3. 从上述模式选择表中选出 **最合适的一个模式**
> 4. 按对应目录约束生成代码
> 5. 如无法决定，默认选择 **策略模式 + 工厂模式** 组合
